Coverage limits and unresolved steps¶

The 600 logical cells combine ten source handoffs, four outputs, five modes and Python/CLI/real-stdio MCP. Acquisition is prepared once per source route, then an independently authored reviewed specification exercises generation semantics. Database aggregates in this matrix are stand-ins; separate live integrations establish actual acquisition. This is not 600 live profiling/inference runs.

The 179 typed model properties, 225 top-level CLI flag occurrences, delegated operation inventory and 131 default MCP argument occurrences are navigation inventories. Finite pair coverage does not establish every possible value, all triples or all option combinations. Supplemental CLI refusal tests do not claim arbitrary internal-exception/debug behavior or per-leaf help coverage.

The 23 full-gate skips comprise ten live integration cases exercised separately, five isolated composition cases exercised separately, six explicitly excluded legacy preservation combinations and two inapplicable retained-destination combinations. Excluded/N/A cases are not counted as passed. Applicable bounded preservation refusal and destination-refusal checks passed separately.

The required six-container baseline passed. Two supplemental live-Trino runs inside final containers remain unexecuted after local dependency/network setup failed; they are outside that baseline and distinct from the successful live database and installed-process tests. Owned database/container resources were cleaned up. Temporary fictional test fixtures are retained with local evidence.

Actual Codex inspection, current-specification human review, new consent and the completed synthetic plan are recorded above, with explicit UI and client-exit observation limits. Automated SDK/PTY cases and permission to publish RC5 do not provide that dataset consent. The current exact-main gates, Ubuntu hashes and manual result do not replace publication or post-publication verification.
