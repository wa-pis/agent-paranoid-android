Roadmap¶

English · Русский

These are directions, not committed dates. Priorities follow user feedback and confirmed defects. Stable 1.6.0 is already published and publicly verified; completed work belongs in release history, not this list.

Now¶

  • Follow up on the remaining external 1.6.0 evidence gaps through the OpenSpec work plan: historical Trino application authentication settings and external profile provenance. The numeric profiling, relational planning/utility, bounded statistics and CLI fixes shipped in the published 1.7.0rc1 candidate; its finite installed checks do not reproduce missing private inputs or the historical 401.
  • Complete remaining transformation evidence: target-size coverage of the final public/configured routes and the separately tracked trust-boundary amendment review. Prior approvals and private scale runs retain their original scope.
  • Improve onboarding from pilot feedback. Versioned guides and four downloadable formats are already published; see documentation versions.
  • Run product-validation pilots on development and analytics workflows.
  • Address confirmed client defects, migration feedback and dependency maintenance.
  • Monitor source/output consistency, portable business rules and MCP permissions.

Next¶

  • Implement the maintainer-selected Cloudflare Pages migration while preserving verified editions, bilingual guides, four download formats, old links and rollback; see the OpenSpec. The first Cloudflare parallel upload passed exact-byte checks for all five retained editions and four downloads. Isolated PR success/failure and private-variable absence are verified. A separate recovery project passed real A/B rollback and identity/hash rejection with unchanged defaults. The canonical switch and final cleanup remain open. RTD evaluation is retained as partial evidence. Native normal and PR builds succeeded; PDF and both ZIP downloads matched their native build. Served HTML gains service scripts, so public integrity, managed version mapping, preview isolation and hosted rollback remain open. GitHub Pages remains the accepted host until parallel acceptance and switch.
  • Design batch-based validation of CSV, JSON and Parquet so complete datasets need not remain in memory. Bound cross-table key and uniqueness checks, preserve deterministic results and measure memory on synthetic fixtures. A separate OpenSpec change is required before implementation.
  • Simplify CSV and database workflows using pilot feedback.
  • Publish runnable examples and short case studies using synthetic fixtures.
  • Improve diagnostics where users repeatedly need help.

Later¶

  • Source-row EAV pivot/unpivot remains deferred. Conditional formulas and source-free EAV modeling shipped in the 1.7.0rc1 candidate; transforming existing EAV rows requires a separate proposal for row cardinality, duplicate/null semantics, typed values, provenance and explicitly authorized source I/O. Neither source-free generation nor one-to-one transformation authorizes it.
  • Consider monthly-date category inference and a separately reviewed configurable local-category ceiling. Neither is implemented; source-preservation defaults remain 20 non-sensitive values of at most 64 characters, with content checks.
  • Add integrations only after demonstrated demand.
  • Consider reporting and validation adapters for concrete workflows.
  • Evolve public contracts through the compatibility and deprecation policy.

The finite fictional transformation/session campaign for stable 1.6.0 completed with explicit coverage limits. That grants no dataset permission. Changed public activation still requires matching specifications, executable evidence and independent exact-source review.
