# AI-интеграция

[English](../ai_integration.md) · Русский

## Для чего это нужно

Advisor помогает предложить изменения DatasetSpec по безопасным метаданным. Его предложение проходит детерминированную проверку, а человек повторно проверяет итоговый контракт.

## Что получится в результате

Локальный review-first workspace и ограниченный advisor exchange JSON. Внешняя отправка не выполняется этими шагами.

## Предварительные требования

Установлен Python 3.11+ и пакет проекта. Терминал открыт в корне репозитория `agent-paranoid-android`; виртуальное окружение активно. Входы — только вымышленные файлы из репозитория. Папка назначения новая; есть права чтения входов и записи результата. Для команд ниже используйте macOS/Linux; в PowerShell вводите каждую команду одной строкой без `\`. Внешние provider-вызовы не проверялись. Для локального plan/request extra openai не требуется.

## Пошаговое выполнение

### Шаг 1. Подготовьте план

**Что сделать:** Создайте workspace из вымышленного CSV и остановитесь до генерации.

**Где выполнить:** Корень checkout.

**Команда или пример:**

```bash
test-data-agent agent-plan examples/csv_quickstart/customers.csv --workspace out/ru-agent --count 25 --seed 12345 --format csv
```

**Что должно произойти:** Созданы profile/spec и состояние ожидания review.

**Как проверить:** agent-status сообщает awaiting_approval.

**Если не получилось:** При занятом workspace выберите новую папку; не удаляйте исходные артефакты.

### Шаг 2. Посмотрите review

**Что сделать:** Получите безопасный checklist и отпечаток текущего spec.

**Где выполнить:** Корень checkout.

**Команда или пример:**

```bash
test-data-agent agent-review out/ru-agent
test-data-agent agent-status out/ru-agent --json
```

**Что должно произойти:** Показаны поля, предположения, privacy и fingerprint.

**Как проверить:** Статус ожидает одобрения; generation ещё не выполнена.

**Если не получилось:** Если источник или spec изменился, заново постройте план или повторите review.

### Шаг 3. Сохраните exchange локально

**Что сделать:** Создайте файл только если out/ru-advisor-exchange.json ещё не существует: перенаправление shell само по себе перезаписывает файл.

**Где выполнить:** Корень checkout.

**Команда или пример:**

```bash
test-data-agent agent-advisor-request out/ru-agent --exchange > out/ru-advisor-exchange.json
```

**Что должно произойти:** Записаны trusted instructions, untrusted metadata и schema AdvisorProposal.

**Как проверить:** JSON читается, содержит fingerprint-bound request; исходных строк нет.

**Если не получилось:** При ненулевом коде не передавайте файл провайдеру: shell мог оставить пустой/ошибочный файл. Проверьте статус workspace.

## Проверка результата

Перед любой внешней отправкой человек проверяет метаданные, имена таблиц/полей, разрешённого провайдера и политику организации. Даже агрегаты и имена могут раскрывать контекст. Сохранение exchange — локальная операция, не разрешение на передачу.

## Типичные ошибки

| Ошибка | Причина | Решение |
| --- | --- | --- |
| Workspace не awaiting_approval | Уже завершён или находится в другой фазе | Выполните agent-status; действуйте по его next action. |
| Proposal не совпадает с fingerprint | Изменился request/spec | Создайте новый exchange; не подменяйте отпечаток. |

## Необязательное обращение к провайдеру

После явного разрешения передачи и установки `.[openai]` можно выполнить `test-data-agent agent-advise out/ru-agent --provider openai`. Runtime `OPENAI_API_KEY` должен внедряться секретным механизмом, не попадать в команды или файл проекта. OpenAI и GigaChat — экспериментальные provider adapters. Для GigaChat: extra `gigachat`, `--provider gigachat`; используйте ровно один из `GIGACHAT_CREDENTIALS` и `GIGACHAT_ACCESS_TOKEN`. TLS обязателен. Эти сетевые команды **не проверены выполнением** в аудите; квота, модель и доступность требуют отдельной проверки.

Для внешнего ручного обмена ответ сохраняется как bounded JSON и принимается через `test-data-agent agent-advisor-apply out/ru-agent advisor_proposal.json`. Схема ответа находится внутри exchange; не придумывайте proposal и не редактируйте spec в обход валидатора.

После любого применения предложения снова выполните `agent-review`, прочитайте изменённый spec и получите согласие на точный fingerprint. Только затем `agent-approve out/ru-agent --reviewed-spec-sha256 <ОДОБРЕННЫЙ_SHA256>` (placeholder заменяется реальным значением; не вставляйте угловые скобки в shell). Нельзя автоматически одобрять всё, что предложил provider.

AI не создаёт строки напрямую, не придумывает таблицы и связи вне локальных кандидатов и не получает право отключать safety. `--local-category` не разрешает передавать исходные enum провайдеру: они заменяются field-scoped synthetic labels. Подробный [контракт advisor](../reference/advisor.md) и [интеграция](ai_integration.md).
