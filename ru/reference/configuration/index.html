Справочник конфигурации¶

English · Русский

Код: core/dataset.py, core/field.py, core/entity.py, core/settings.py, limits.py, postgres_config.py, trino_config.py. JSON Schema: dataset_spec.schema.json. Версия пакета 1.6.0 и DatasetSpec schema_version: "1.1" — разные версии. Совместимость с 1.0 сохраняется без decimal; при импорте payload без schema_version используется legacy 1.0, тогда как новый Python DatasetSpec по умолчанию создаёт 1.1. Указывайте версию явно.

В validation_settings validate_schema, validate_relationships, validate_constraints, validate_privacy по умолчанию true, fail_fast — false. Не отключайте секции для получения положительного результата. Обязательные post-solve type/privacy проверки генератора не отменяются настройками отчёта.

synthetic_identifier может задавать pool_size — положительное целое число синтетических ключей для повторяемого ID. Для primary key pool не может быть меньше row_count. Это число, а не сохранённая карта реальных идентификаторов. Типы распределений и полные вложенные модели: DatasetProfile и DatasetSpec.

Приоритет¶

Явный CLI override меняет соответствующий параметр spec: count, seed, mode, invalid_ratio, format. Если override не задан, используются сохранённые настройки и defaults конкретного пути. Значения defaults команд перечислены в CLI; для generate не переносите defaults сокращённой CSV-команды по догадке. Переменные окружения управляют только перечисленными в коде интеграциями и бюджетами; они сами по себе не включают AI.

Полный перечень параметров подключения, per-query scan/time limits, допустимых единиц, audit actor/size и transport budgets сохранён в расширенном справочнике. Перед изменением конкретного интеграционного параметра прочитайте его строку там; значения из разных единиц не взаимозаменяемы. Не включайте insecure/unrestricted overrides ради обхода ошибки.

Проверка локальной конфигурации: диагностика. Проверка результата: валидация.

Режимы и точные значения 1.6.0¶

edge создаёт валидные границы, но constraints и business rules могут заменить отдельную границу; маленький count не покрывает всё. load_test умножает row_count на load_multiplier (по умолчанию 10); явный --count задаёт точное число без умножения. Повторяемость требует тот же порядок entities в spec, seed и окружение. Python core дополнительно поддерживает signed 64-bit отрицательный seed для совместимости; сохранённый spec — только 0…2**63-1.

decimal требует schema_version 1.1 и distribution.kind=decimal_range с precision≤38, scale и строковыми min/max. numeric_measure разрешён только для явно проверенной нечувствительной numeric меры; sensitive flags, names и identifiers имеют veto. Пример: DECIMAL.

Трансформация использует отдельные BehaviorPolicy/BatchProfile schema_version 0.1; их нельзя подавать вместо DatasetSpec. resource_limits и TEST_DATA_AGENT_TRANSFORM_* настраивают её acquisition/decoding, а run caps могут понижать, не молча расширять session/profile ceilings. Полный перечень и единицы: transformation input limits. Receipt и точный snapshot не заменяются переменной окружения.
